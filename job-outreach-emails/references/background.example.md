# Background — asset pool (filled-in example)

*This is one real user's file, kept as a model of what a good asset pool looks like — note how every project is described by the problem it solved, and every personal thread has proof attached. Do not pull from this file when drafting. The live file is `background.md`.*

**This is a menu, not a résumé.** Pull the one or two items that genuinely connect to this person, company, or role. An email that lists four accomplishments is weaker than one that lists the right one. What's relevant changes completely depending on whether the company is proptech, dev-tools, or consumer — and depending on what the user actually wants to foreground that day. When unsure which asset fits, ask them rather than including all of them.

The user maintains this file. If something here is stale or they correct a detail mid-conversation, treat what they say as authoritative and mention that the file is worth updating.

## Identity line

The parenthetical they use to establish credibility without a paragraph:

Variations: "as a technical PM," "[degree] at [school]." Use when the email needs them situated fast — usually right before the ask.

## How to use a bridge honestly

The bridge works because it's true. Never stretch one — if the founder collected stamps and the user collects coins, that's not a bridge, that's a reach, and it reads as one. Better to skip the personal hook and lead with substance than to manufacture a shared thread.
